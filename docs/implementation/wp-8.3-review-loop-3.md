# WP8.3 — Review loop 3

**Branch** `wp/8.3-review-loop-3` · **Milestone** M8 · **Date** 2026-09-04 · **Ask** Mircea:
review the code and critique it from five perspectives — full-stack developer, distributed-systems
developer, security engineer, technical writer, DevOps engineer — get the individual feedback,
aggregate, critique, incorporate; three loops. This is loop three, the last, on the tree with loops
one and two merged.

## How the loop ran

Five fresh reviewers (independent agents, read-only, no AWS access), each given both earlier notes
first so they would check what those claimed, each returned at most twelve findings. Three of the
five were stopped half-way by an API spending limit and resumed forty minutes later on the same
tree; the technical-writing and full-stack fixes had landed meanwhile, which the resumed reviewers
were told, and their citations were re-checked against the final tree. Their 57 findings
de-duplicated into the table below (plus one the browser suite found afterwards); each was accepted, deferred with a reason, or rejected with the
reason (the critique). Of the 46 rows, 43 are accepted in full or in part (9 of them with a part deferred, and one with a part rejected), 3 deferred whole, none rejected whole; one row (46) is a finding of the suite itself, not of a reviewer. The accepted ones landed on this branch with tests; CI gates the
merge; the deploy and three unattended demo passes follow.

Loop two's claims that did not hold are marked *loop-2 regression*: the README typo fix missed
because the phrase breaks across a line; four AWS tasks were left without the scoped identity; the
pointer's `retiring` record was written but never parsed back, so the crash-safe retire never ran
on AWS; the canary looked for a `state` field the session function never emits; the periodic
snapshotter had no phase gate; `deploy:stacks` never reached the runbook; the blob cache still
bumped its version on a miss; the loop-1 note's counts still did not add up. All are fixed here.

## Tests

- Core (`review-loop-3.test.ts` and the adapted suites): once-per-attempt charging and the ignored replayed release, the deadline doubled per release and capped at three doublings, the `lost` outcome that does not count, the machine presign budget answering with nothing while a connection's own budget still closes; the heartbeat window and the two-second health announcement, the destructive set (skip and a running kill; a queued drop and the redundancy flip stay free), the machine-wide presign and launch budgets (tokens in the harness and the simulation), `seq` advancing unobserved; protocol: the canvas cap in the property test and a full `presigned` reply.
- Fleet: `retiring` and the pin round-trip through the codec, the early `pending` record, the two-pass `down`, the canary's three bodies, the session memo.
- Control plane: the lease self-check (drains and terminates when superseded, carries on when named), the standby flag — a control plane the pointer does not name reports `authoritative: false` on `/health` and flips once the pointer names it.
- Infra: every COPY source exists in the placeholder directory; every AWS-touching task carries the identity and the guard; no RunMicrovm statement names a wildcard image.
- Node: a module fetch that hangs releases the task at its deadline. Store: every fetch is bounded.
- Web: kept controls across a resubscribe, the reset backoff, the machine-full state, the bundle-matched launch, the stopped result box; the browser suites pass locally under the region's policy.
- Every browser suite passes locally; the CDK app synthesises without credentials (as CI does).
