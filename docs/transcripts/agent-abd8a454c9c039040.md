## Summary

The core is unusually well-shaped: a pure `(ledger, event, now) → effects` function with explicit invariants, a seeded churn simulation, hash-only state, and generation-stamped messages make the node-churn story genuinely robust, and I found no ordering bug in results, twins, contest rounds, or sequence numbers. The weak seam is everything the pure function cannot see — asynchronous effects, the store, the process's own lifecycle across a rotation — where effects are fire-and-forget, the successor never re-derives them, a predecessor keeps acting after it has handed over, and one node's transient error is treated as a program fault. Fix first: re-derive pending stage effects on adopt/tick with retries (1), cap params/page 0 and stop `encode` from throwing through `dispatch` (2), and map node store failures to `RELEASED` with retries (3); then gate ticks, fleet, and `latest` writes on `phase === "active"` and add the handover lease (4, 5).
