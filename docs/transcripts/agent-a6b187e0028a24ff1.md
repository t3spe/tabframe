## Summary

The operational posture is thoughtful for a one-person demo — a genuinely idempotent rotate with a `pending` record, least-privilege roles, a whoami guard, clean transcripts, a notification-only budget, and honest documentation of platform limits — but it is entirely reactive: nothing alarms, the platform drops the control plane's logs after the first line, and rotate's failures are reported as successes, so an outage is discovered by a visitor. The deploy path builds the image from the working tree in parallel with the tests, cannot be traced to a commit, has no verified rollback, and would rebuild a different image tomorrow from the same commit. Fix first: (1) serialize `deploy` as build then test with a clean-tree and green-main guard and a commit stamp; (2) make rotate failures throw and add alarms plus a session-URL canary; (3) terminate and re-token a successor that never reaches RUNNING, and turn rollback into a real task that pins cores too.
