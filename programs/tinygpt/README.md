# tinygpt

Runs greedy continuations from a 0.8 M-parameter character-level GPT trained on *Moby-Dick*, the
whole forward pass in WebAssembly on the cores. It is the program that shows the machine is general:
one continuation per task, the same bytes from every core, four milliseconds a token.

## How it works

- **Model.** 97-symbol byte vocabulary, context 128, 4 layers, 4 heads, width 128, pre-norm, tanh
  GELU, learned positions, tied output embedding — 822,144 weights. `train/train.py` trains it in
  PyTorch on the word-count corpus (3000 steps, seed 1, CPU) and writes `in/weights.bin` and
  `train/reference.json`.
- **Weights file.** A `TGPT` magic, a version, the five shape numbers, the vocabulary bytes, then 52
  tensors, each an f32 scale, a count, and that many int8 values (symmetric per-tensor
  quantisation). Bytes outside the vocabulary map to symbol 0.
- **Stage 0, `generate`.** One task per prompt (`prompts` split on `|`, trimmed, at most 64;
  "Call me Ishmael" if none). The task's input is the prompt and the token count; its output is the
  prompt followed by the generated bytes. The forward pass runs in f32 with a fixed summation order
  and a per-layer KV cache, recomputing from the last 64 symbols once the window fills, so every
  core produces the same continuation.
- **Stage 1, `collect`.** One task reads `/out/0/…` in index order and joins the continuations with
  blank lines into the text the dashboard shows.
- **Stage 2.** `plan` ends the execution with no follow-up.

## Parameters

| Name | Meaning | Default |
|---|---|---|
| `prompts` | prompts separated by `\|` | `"Call me Ishmael\|The whale\|It was\|Ahab"` |
| `tokens` | symbols to generate per prompt | `96` |

Imports `tf.stat`, `tf.read`, `tf.list`, `tf.log`, and `env.abort`.

## Checked by

`train/reference.json` holds, for four prompts, the prompt ids, the last-position logits, 24 greedy
ids, and the text, computed by the training script from the dequantised weights.
`packages/sdk-as/test/tinygpt.test.ts` runs the staged program with `tokens: 24` and requires
agreement token for token with at most one divergence per prompt (f32 summation order), identical
hashes across two runs, and every prompt present in the collected text; it is skipped when the
weights or the reference are absent. There is no `goldens.json`: `mise run goldens` covers
mandelbrot and wordcount. The feasibility study that preceded the program is
[`docs/feasibility-transformer.md`](../../docs/feasibility-transformer.md).
